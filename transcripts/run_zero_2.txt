API moves (prefer zod 4's new surface, no wrappers):
- src/schemas.ts: string-format checks became top-level schemas — z.string().uuid()/email()/url()/ip() -> z.guid()/z.email()/z.url()/z.ipv4()|z.ipv6().
- z.nativeEnum(Plan) -> z.enum(Plan) (zod 4 unified enum handling).
- z.record(z.boolean()) -> z.record(z.string(), z.boolean()) (key schema is now required).
- z.function().args(...).returns(...) -> z.function({ input: [...], output: ... }); Hook.implement still type-checks the callback, so the test's inferred (event, bytes) params stay typed.
- .default("3")/.default("8080")/.default({}) -> .prefault(...): in zod 4 .default() is the *output* type and bypasses the schema, while .prefault() feeds the fallback through the schema — which is what zod 3 did, so "8080" still transforms to 8080 and prefs.{} still fills theme="light", retries=3.
- src/validate.ts: ZodError.errors -> ZodError.issues (fixes the implicit-any on the map callback too).

Behaviour preserved where zod 4 silently tightened rules (found by the corpus, 33 diffs -> 0):
- id: z.uuid() now enforces RFC 9562 version/variant bits and rejected 24 real non-conforming ids; z.guid() is zod 3's plain 8-4-4-4-12 check.

- age: zod 4's .int() means *safe* integer; zod 3's was Number.isInteger — kept via a refinement so 1e21 and 2^53 are still accepted.
- ip: zod 4's IPv6 check rejects a scope/zone suffix like "fe80::1%eth0"; added a third union branch that validates the address half with z.ipv6() and leaves the value untouched.
